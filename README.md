# buff_notifier

Уведомления в Telegram о выгодных лотах на BuffMarket: лот дешевле рынка или
дорогой float по обычной цене. «Рынок» — история продаж CSFloat из базы
CSFloat-бота. Вводная — `csfloatpricesparcing/docs/BUFF_NOTIFIER.md`.

Установка, веб-панель и DuckDNS — **[docs/DEPLOY.md](docs/DEPLOY.md)**.

## Текущий этап

- Реализован параллельный опрос через несколько аккаунтов с постоянными
  прокси. Дополнительные профили добавляются через вкладку «Аккаунты»:
  сохранение → проверка сессии и исходящего IP → включение.
  Без добавленных профилей работает прежний основной аккаунт.
  Цель — 2000–3000 предметов каждые 5 минут. Число аккаунтов и адресов
  определяем по фактической устойчивой скорости и ограничениям.
- База CSFloat-бота только читается (`mode=ro`). Сам бот не меняется.

## Как устроено

```
run_notifier.py   пул аккаунтов: следующий предмет по кругу → sell_order →
                  оценка лотов → Telegram (по лоту не больше одного раза)
run_web.py        веб-панель на 127.0.0.1:5050: настройки, сессия, прокси,
                  Telegram, список предметов, сигналы
data/settings.json  пороги, комиссии, темп — правятся из панели
data/buff.db        список предметов, виденные лоты, сигналы, состояние
data/accounts.json (600)  сессии/прокси дополнительных аккаунтов, настройки профилей
.env (600)          сессия BuffMarket, прокси, токен Telegram, хэш пароля
```

Обе службы читают настройки, `.env` и профили заново на каждом шаге: изменения из
панели действуют без перезапуска.

- `notifier/judge.py` — два сигнала. Рынок — продажи CSFloat за окно по
  ликвидности (16 дней, для редких 30/45), приведённые к сегодняшним ценам.
  База сравнения выбирается: диапазон float (сотая, минимум 5 продаж), весь
  предмет (минимум 3), оба условия или любое из двух. Отдельно выбирается
  скидка от медианы либо от выручки после комиссии. Выгода в долларах и
  процентах от затрат считается после комиссий; это отдельные фильтры.
  Ванильные ножи оцениваются по всему предмету, даже без float.
  Паттерновые скины (Fade, Marble Fade, Case Hardened, Crimson Web) — пропуск.
- `notifier/poller.py` — непрерывный обход всех активных предметов по кругу,
  с сохранением позиции после перезапуска. После последнего предмета новый
  круг начинается сразу. Продажи CSFloat нужны для оценки цены, не для
  расписания. Скорость задаётся паузой между запросами. Поиск goods_id
  получает один запрос после четырёх опросов каждого аккаунта.
- `notifier/pool.py`, `accounts.py` — до 200 профилей, максимум 32 запроса
  одновременно. Каждый обработчик имеет отдельные HTTP/SQLite соединения,
  сессию, интервал и замер. Атомарная общая очередь не выдаёт один предмет
  двум обработчикам одновременно. Сигналы защищены общим уникальным ID лота.
  Одинаковый проверенный исходящий IP делит темп (самая длинная пауза
  его включённых профилей) и cooldown; 429 одного адреса не останавливает
  остальные адреса. Истёкшая сессия останавливает свой аккаунт. При 429
  сохраняется Retry-After или пауза 15 минут. После перезапуска сохраняются
  cooldown и очередь, незавершённые задания резервируются на 120 секунд
  с продлением во время работы.
- `notifier/browser_login.py` — вход в Steam в отдельном Chromium через
  прокси аккаунта. Логин/пароль подставляются в форму Steam; пароль живёт
  только в памяти текущего задания. При необходимости доступны капча/Guard
  и ручное управление браузером из защищённой панели. После входа cookies,
  CSRF и User-Agent сохраняются только после успешной проверки Buff API.
  Браузерные профили в `data/browser_profiles` (700, вне Git) сохраняют
  авторизацию; они отделены по аккаунту, прокси и хэшу логина. Один вход
  одновременно, таймаут 10 минут. На время входа общий IP резервируется,
  остальные IP продолжают работать. Действующий 429/cooldown сохраняется.
  Смена/удаление профиля в процессе входа не позволяет перезаписать его
  сессию. Скриншоты и данные формы не записываются в файлы или журналы.
- На «Обзоре» есть замер запросов: успешные опросы и поиски, ошибки,
  первое и последующие 429, Retry-After и фактические запросы за последний
  час с учётом пауз. «Обзор» показывает также общий результат всех аккаунтов
  за 5 минут/час, «Аккаунты» — отдельный замер каждого профиля.
  Это пассивный учёт работы службы, без дополнительных
  запросов. Ручные проверки из панели и пробника не учитываются.
  Смена сессии, User-Agent, CSRF, прокси, паузы или режима опроса начинает новый замер;
  перезапуск службы сохраняет его. Cookies и адреса прокси в статистике
  не сохраняются. Подробные события хранятся 7 дней, итоговые счётчики —
  без удаления. Теоретическая ёмкость в «Нагрузке» не является лимитом Buff.

## Добавление аккаунта

В «Предметах» и «Аккаунтах» есть поиск, фильтр состояния и страницы по
25/50/100 строк. Галочками можно включать и выключать выбранные строки,
а предметы — также удалять. «Вся страница» выбирает только показанные строки.
Управление сессией и прокси аккаунта раскрывается в его строке.
Поиск goods_id просматривает следующие страницы выдачи; для ненайденных
предметов есть повторный поиск. `Survival Knife` распознаётся как
`★ Survival Knife`, при этом StatTrak и ножи с покрытиями остаются разными.
Уведомления Telegram сокращены; время выставления и окончания паузы — МСК.

В «Аккаунтах» заполните название, постоянный прокси, логин и пароль Steam,
нажмите «Создать профиль и войти через Steam». После проверки сессии нажмите
«Включить». Для существующего аккаунта есть «Войти через Steam / обновить
сессию автоматически». Пустые логин/пароль используют сохранённый браузер
или позволяют войти вручную. Поддерживаются HTTP/HTTPS-прокси с авторизацией
и SOCKS5 без авторизации (ограничение Chromium). Для SOCKS5 с авторизацией
остаётся ручной импорт curl. Если Steam требует Guard/капчу, завершите их
в показанном окне. Полностью автоматический вход зависит от требований Steam.

Для массового добавления откройте «Массовое добавление аккаунтов и прокси»
под списком «Аккаунтов» и вставьте по одному логину в
строке (`login:password`) и отдельный список прокси в таком же порядке:
`host:port:login:password`, `host:port` или URL. Можно вместо двух списков
использовать `login;password;proxy`. Пароль с `;` заключите в двойные
кавычки, внутреннюю двойную кавычку удвойте. Пустой список прокси означает
адрес сервера для всех; `-` в отдельной строке — для соответствующего
аккаунта. Один общий прокси требует отдельной отметки и сохраняет общий
темп, как другие аккаунты с одинаковым выходным IP.

Перед добавлением проверяется весь список: при ошибке формата, несовпадении
числа прокси или превышении предела профили не создаются. Входы идут
последовательно; результат каждого виден в очереди. По умолчанию успешно
проверенный аккаунт сразу включается для опроса. Эту отметку можно убрать.
Ошибки входа не останавливают остальные аккаунты; при капче есть ссылка
на окно текущего входа. Новые профили остаются выключенными до проверки.

Повторный импорт того же Steam-логина использует существующий профиль и
пропускает работающую проверенную сессию. Прокси должен совпадать с
сохранённым; его изменение выполняется отдельно. Интервал из массовой
формы применяется к новым профилям. Общий предел — 200, включая основной.
Steam-пароли не сохраняются в файлах или журналах: очередь живёт в памяти,
выход из панели, отмена или перезапуск службы очищают её. После перезапуска
для продолжения вставьте исходный список заново; созданные профили и
проверенные сессии сохраняются.

Ручной вариант через curl:

1. В отдельном профиле браузера подключите постоянный прокси и войдите
   нужным Steam-аккаунтом на `buff.market`.
2. Откройте страницу предмета и DevTools → Network. Найдите GET
   `sell_order`, нажмите Copy → Copy as cURL (bash).
3. В защищённой панели «Аккаунты» вставьте curl, название и тот же прокси
   (`http://логин:пароль@host:port` или `socks5://…`). Начальная пауза — 5 с.
4. Сохраните выключенным, нажмите «Проверить сессию и IP», затем «Включить».
   При занятом IP дождитесь паузы; проверка делает один запрос к Buff и
   отдельную проверку адреса через ipify. Ручные проверки не входят в замер.

Для первого сравнения достаточно двух дополнительных аккаунтов и адресов.
Проверка адреса — снимок, поэтому прокси должны иметь постоянный выходной
IP. Сервис не переключает адреса после 429. Результаты покажут реальную
пропускную способность; независимость лимитов на аккаунт/IP не предполагается.
При паузе 5 с и одной странице на предмет 20 разных IP дают теоретически
240 запросов/мин, тогда как цель требует 400–600 запросов/мин. Поиски,
обработка, сеть и cooldown уменьшают фактическую скорость.
- `notifier/estimate.py`, `recency.py`, `phases.py` — перенесены из
  `csfloatpricesparcing/src` (коммит в шапке файла) без изменений в логике.
  Перенос, а не импорт по пути: перестановка внутри бота не должна молча
  ломать уведомления. Связь с ботом — только схема базы.
- `notifier/buff.py`, `listings.py` — запрос страницы предмета
  `api.buff.market/api/market/goods/sell_order` и разбор ответа (образец в
  `tests/fixtures`). Без входа сайт отвечает `Login Required`.

## Инструменты

```bash
.venv/bin/python -m tools.set_password        # пароль веб-панели
.venv/bin/python -m tools.set_session         # сессия из «Copy as cURL» (или в панели)
.venv/bin/python -m tools.probe 5777          # один запрос: форма ответа и лоты
.venv/bin/python -m tools.find_goods "AK-47 | Redline (Field-Tested)"   # goods_id по названию
.venv/bin/python -m tools.pull_csfloat        # копия базы бота с его сервера
.venv/bin/python -m pytest -q
BUFF_TEST_BROWSER=1 .venv/bin/python -m pytest -q tests/test_browser_login.py
```
